## Architecture Summary

One vertical slice is delivered and it is the slice the sprint promised. `LocalFilesConnector` discovers files under declared roots, hashes their bytes, and diffs them against a JSON snapshot cursor; `SQLiteRepository` persists items, permissions, chunks, an append-only journal, and receipts transactionally per item; `chunking.py` produces deterministic heading- or paragraph-aligned slices; `retrieval.py` is a candidate provider over SQLite FTS5/BM25 that returns `SearchHit` rows and never evidence; `governance.retrieve()` is the only public call that assembles an `EvidenceBundle`, and it evaluates permissions over provider candidates before any `Evidence` object exists. `lee-kb init｜sync｜search` is a thin surface over that library and reaches evidence only through the governed call.

The layering holds under inspection. `PermissionEvaluator`, `Repository`, and the connector contract are ABCs, so the single-user evaluator, SQLite persistence, and lexical ranking are each replaceable without touching the composition in `governance.retrieve()`. Retrieval returns evidence and nothing executable — no code path in `src/lee_kb/` acts on retrieved text. Runtime dependencies remain empty (`pyproject.toml:23-25`); the only third-party names are the `dev` extras.

The prior High finding (S1-R-01, a second ungoverned evidence surface) is genuinely fixed and now regression-guarded: `lee_kb.retrieval` exports only `LEXICAL_RETRIEVER`, `LexicalRetriever`, and `StaleEvidenceError` (`retrieval.py:24`), `LexicalRetriever` exposes `search()` only, and the package-wide sweep at `tests/test_governance.py:180-211` fails if any other public callable is annotated to return an `EvidenceBundle`.

## Residual Risks

- **Office formats (.docx/.xlsx/.pptx) are deferred implementation, not deferred contract.** `DocumentType` enumerates them and `FORMAT_HANDLERS` (`local_files.py:117-122`) is shaped to accept handlers, but none is registered, so those files are silently invisible to discovery — they are not reported as skips or warnings. Against the Employee Zero parity criterion this is the largest open gap: a corpus containing Word or Excel documents will synchronize, report success, and omit them. The blocker is dependency approval (`context.md` Next Action 3), not design. A cheap mitigation before then: count and report files that match an include pattern but have no registered handler.
- **The curated golden benchmark does not exist yet.** The committed corpus is drawn from this repository's own documents; hit-at-10 is saturated at 100%, so only hit-at-1 and MRR carry signal. The document says so plainly; the risk is a later reader treating the seed numbers as the adoption gate for semantic retrieval.
- **`--principal` is an unauthenticated assertion.** `lee-kb search --principal anyone@example.com` (`main.py:378-379`) is accepted as given, so at the CLI the permission model is advisory: any local user who can read the SQLite file can also name any principal. Acceptable for a single-user personal deployment where the file is readable anyway; it must not survive into a multi-user or service surface.
- **Cross-project widening has no entitlement check.** `filters.projects` can widen a query beyond `request.project`, and only per-item permissions push back. Harmless personally; for the tenancy story where project *is* the isolation boundary this is Sprint 1 Open Question 1 and needs an answer before a second tenant exists.
- **The receipt records who, not why.** No `permission_basis` field, so "under what permission was this released?" is unanswerable from the receipt alone (`docs/sprint-1-contracts.md` Open Question 2).
- **Candidate retrieval fetches to exhaustion under OR matching.** `LexicalRetriever._search_project` (`retrieval.py:63-76`) re-runs the FTS query with a doubling limit until the result set is smaller than the limit, materializing every matching chunk's full text. With the S1-R-11 OR matcher a natural-language question expands to a disjunction of its content tokens (probe: `"what changed this week?"` → `"changed" OR "week"`), so a common-word query over the ~1,200-document Employee Zero corpus can pull a large fraction of the corpus through several repeated queries. Correct, but measure it against the real corpus before Next Action 1 is called done.
- **`FreshnessRequirement.allow_refresh` is accepted and does nothing.** Probe: `allow_refresh=True` yields `refreshed=False`. The report stays honest — no caller is told a refresh ran — but the flag reads as implemented.
- **Tag filtering semantics are unpinned.** `docs/sprint-1-contracts.md` says "equality against `KnowledgeItem.tags`"; `retrieval.py:85` requires *all* requested tags to be present. Pin the intended reading before a consumer depends on the other one.
- **This checkout has never synchronized real data.** No `knowledge/sources.toml` and no Employee Zero roots are present; the connector has been exercised against fixtures and a scratch corpus only. `context.md` and `sprint-plan.md` both say so, which is the right handling — but the parity claim stays unproven until Next Action 1 runs.
- **No preserved validator record covers the reviewed tree.** Every preserved system-validator result predates the S1-R-01/10/11 repair commits (`3219f93`, `717b11b`). The repairs' green suite is a worker assertion; my own checks (below) are static analysis plus targeted probes, not a suite re-run, because validator rerun is not permitted for this step.
- **Reviewer handoff is incomplete by design.** `agents/reviewer.md` also asks for a summary in `feedback.md`; this step's write scope is `code-reviews/` only, so the actionable items above are not mirrored there. Whoever closes the sprint should copy the Medium findings into `feedback.md`.
